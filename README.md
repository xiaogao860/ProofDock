# ProofDock

本地最小原型：钱包、ERC-20 测试资金、发布质押、付费查询与分成、挑战、手动测试裁定、资金领取和质押退出。Remix 的 x402 付款执行入口与挑战后的本地自动复验已接入；真实付款默认关闭，尚未完成付费实测。OneCompiler 接口预留。

## 网页入口
新版网站采用纯灰背景与黑白灰交互，顶部是固定、贴边的半透明毛玻璃导航。页面标题为 ProofDock，本地字体和标志随源码提供。

- 服务记录：调用本地 Solidity 编译服务，签名保存执行材料，再自愿质押发布。
- 上链记录：浏览公开摘要、付费读取完整材料、发起挑战并查看复验结果。
- API 接入：展示 HTTP 接口与示例，提供连接测试和调用日志。
- 我的资产：查看测试资金、个人记录、资金领取与质押退出。

浏览器钱包交互和网页操作共用 `web/lib/proofdock-client.mjs`。Agent 可直接调用 HTTP API，并在自身钱包中签名；接口不接收私钥。完整调用协议见 [Agent HTTP API 文档](docs/Agent-HTTP-API.md)。

## 启动
双击 `启动.command`，访问 http://127.0.0.1:4319。双击 `停止.command` 关闭本项目进程。每次重启重置链和演示记录。系统需要 Node.js 24（SQLite 使用 Node 内置模块）；脚本优先使用本机 Codex 内置 Node。启动终端保持打开；每次启动使用已构建网站，修改页面后需重新构建。钱包交互使用 ethers.js，减少最小版本的依赖；后续可迁移 wagmi/viem。

首次安装依赖：使用 pnpm install。项目锁定实际依赖版本。Ganache 可使用纯 JavaScript 实现，原生加速扩展不是必要组件。

## 钱包
连接 MetaMask 等浏览器钱包，点击“切换网络”；未知网络会提示添加本地链。RPC http://127.0.0.1:8545，chain ID 31337。开发账户来自 Ganache deterministic 模式的公开助记词：

`myth like bonus scare over problem client lizard pioneer submit female collect`

仅在专门的测试钱包导入，不给这些公开账户转入任何真实资产。前端无私钥。账户 0 平台；1 发布者；2 查询/挑战者；3 指定验证者；4 备用用户。后四个账户初始化 1000 DCR，测试 ETH 用于 gas。

## 演示
发布者发布执行材料并质押 10 DCR。查询者付 1 DCR，70% 归发布者、30% 归演示平台（未建立专门复验储备）。查询者必须签署请求才能获得付款关联详情。挑战者质押 5 DCR。后台在挑战后用固定 solc 0.8.30 自动复验；履约记录详情展示报告，合约保留指定验证者的手动裁定方法。结论：支持则保证金归发布者；记录错误则发布质押及挑战本金归挑战者；无法验证则退挑战本金。挑战 5 分钟无结论可超时退挑战本金。退出等待 60 秒，争议期不能退出。裁定/退出先记账，本人领取；每笔交易由操作者承担 gas。

## 真实性和信任边界
未调用真实服务时仍为发布者签名的演示凭证。真实执行入口仅接受适配器保存的原始响应，不是第三方履约签名。自动复验检查固定输入的 ABI 与完整字节码一致性，不证明历史调用或支付确实发生；仍是单一指定验证者。链外材料使用本地 SQLite，付费 API 为集中式交付；公开链上摘要不受付费墙保护。v1 API 的读取签名绑定网络、合约、记录、付款编号、钱包和最长五分钟有效期；已有付款凭证可复用，授权过期后重新取得报价并签名。旧版详情接口保留兼容。无生产资金保障或安全审计。未接入 ERC-8004。

## 接口
GET /api?action=services：服务目录。
GET /api：公开记录摘要。
GET /api?action=execute 或 verify：501 尚未实现。
GET/POST /api/remix：免费报价、付款执行和原付款者签名恢复结果。付款需显式设置 PROOFDOCK_ENABLE_REMIX_PAYMENT=1；本轮按用户要求保持关闭。
GET /api/verification：后台状态及公开验证报告。
POST /api：提交签名材料（链上发布成功后才出现在目录）。
GET /api?action=detail&id=...&queryId=...&address=...&signature=...：核对钱包签名和链上付款后获取详情。
服务/复验适配器契约见 adapters/index.ts。

## 验证
node tests/api.mjs 验证 API 付款、签名和材料交付。node tests/flow.mjs 在已部署的本地链上验证资金与权限（会更改测试数据和时间）。node node_modules/next/dist/bin/next build web 验证网站构建。

`pnpm run test:frontend` 在隔离链和临时数据库验证前端客户端的编译、签名保存、质押发布、重复发布、付款后取消签名恢复、凭证复用、挑战复编译和退出领取；需要本地编译服务 4320 正在运行。`pnpm run test:wallet-network` 验证已知网络切换、未知网络添加、用户取消和钱包错误。`pnpm run test:agent-api` 在隔离链验证 HTTP 查询、付款及授权，不修改当前演示链。

运行时钱包文件、SQLite、部署配置、日志和构建产物不进入仓库。重新部署会生成本机配置；Agent 钱包需按 [独立钱包文档](docs/Agent独立钱包.md) 创建。
