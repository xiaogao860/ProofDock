# ProofDock：真实编译与自动挑战验证

更新日期：2026-10-07。

## 当前结果

网站已准备 Remix x402 付款编译入口；遵循“先接完功能，暂不付款”，真实付款默认关闭。官方免费接口与 HTTP 402 已真实访问，0.01 USDC 编译费在 Base 主网支付。尚未产生真实付费编译例子，不能用本地测试样本代替该证据。

自动验证后台已接入本地链：监听挑战事件，读取原材料，在独立子进程中使用已安装的 solc 0.8.30 重编译，再由指定验证者提交裁定。固定完整版本为 v0.8.30+commit.73712a01。

## 使用流程

1. 网站“真实服务探测”内免费获取报价，示例输入为 Counter.sol，优化 enabled=true、runs=200，EVM 为 Shanghai。
2. 将来启用付款后，使用用户自己的 Base 主网钱包确认单次 0.01 USDC 授权。公开 Ganache 测试账户不能作为真实资产钱包使用。
3. 适配器保存请求、版本、设置、响应、哈希、观察时间和结算响应头。收到 HTTP 200 时仍检查 success，不将编译错误误标为成功。
4. 使用实际响应进入“发布与质押”。切回本地链，使用同一地址签名、质押 10 DCR 后自愿发布。未发布不会进入公共目录。真实材料必须匹配服务器保存的原响应，不能自行替换。
5. 查询者正常付 1 DCR 查阅。挑战者提交挑战并锁定 5 DCR；自动验证后台随后复验，无需导入验证者钱包手动裁定。
6. 在“挑战与自动复验”查看结论、原因、比较摘要、报告哈希、裁定交易和验证者。后台每约 2 秒发现一次新挑战，编译和交易确认另需时间。

## 自动验证规则

先检查发布者签名、链上摘要及材料完整性。链外材料损坏或缺失不能恢复原事实，返回无法验证，不以此惩罚发布者。

支持的编译记录按原输入重编译，完整比较合约集合、ABI、创建字节码和运行字节码。对象键排序规范化；字节码只规范化 0x 前缀和大小写，不移除元数据尾部以掩盖差异。

- 一致：支持记录，5 DCR 挑战保证金记给发布者。
- 不一致：签名记录内哈希不符、承诺成功却按原输入编译错误，或编译产物不同；记录标记错误，15 DCR 记给挑战者。这是记录一致性裁定，不表示已经认定服务方主观造假。
- 无法验证：演示材料、不支持的版本、非成功编译记录、输入/产物缺失、运行超时或编译器故障；5 DCR 退给挑战者。

未挑战不自动执行。重复挑战按链上挑战交易分别建立报告，避免重复裁定。存证表中不存在的材料也会返回无法验证。

## 费用和权限

真实编译费使用 Base USDC；质押、查询和挑战使用本地 DCR；本地交易 gas 使用测试 ETH。挑战者承担挑战交易 gas，自动验证者承担裁定交易 gas。

支付采用 EIP-712 / EIP-3009 签名，服务 facilitator 执行结算。服务响应头在当前实现中不一定包含交易哈希，不能把该头当作独立核验过的付款证明。付款凭证仅允许固定服务、Base USDC、固定收款地址和 0.01 金额，不保存用户私钥。默认付款入口返回 403。

一次报价仅可提交一次。请求超时后支付可能已经结算，状态记为 uncertain，禁止自动再次付款。结果恢复由原付款钱包签署读取消息，不再次付费。服务编译失败也可能已收取费用，不保证自动退款。

## 实现位置

- adapters/remix.mjs：固定官方 HTTPS 服务调用。
- lib/payment.mjs：报价和付款签名约束。
- lib/store.mjs / lib/receipt.mjs：原响应、材料与报告保存。
- web/app/api/remix/route.js：报价、执行、恢复。
- verification/compiler-child.mjs / verify.mjs：独立编译子进程和比较规则。
- verification/process.mjs / scripts/validator.mjs：监听挑战、保存报告和自动裁定。
- web/app/api/verification/route.js：后台状态和报告。
- web/components/RemixProbe.js：钱包付款、返回与自愿发布入口。

启动脚本会启动验证者；停止脚本会停止它。当前链未重置。完整重新启动仍会重置链和本地演示数据库，请先导出需要保留的材料。

## 已验证与尚未验证

已验证：官方免费报价、默认禁止付款、签名金额与收款人约束；模拟服务响应下的执行/防重复/结果恢复/原材料发布；隔离链上的三种裁定、分配、报告哈希上链、后台监听、重复挑战与材料缺失。

尚未验证：Base 主网真实付款、Remix 实际编译结果和官方服务的实际参数应用。公开 HTTP 源码中没有明确把 settings 设置到 compiler；这是源码审查推断，线上版本仍需实测，不能用请求回显代替产物验证。

该机制仍信任单一指定验证者以及本地材料存储。编译一致性不证明历史调用确实发生、提供方签名真实或服务当前可靠。没有接入 ERC-8004、多验证者共识、其他编译器版本和生产审计。
